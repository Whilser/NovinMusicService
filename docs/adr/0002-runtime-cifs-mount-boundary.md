## Контекст

Адрес и имя SMB-шары меняются через веб-настройки после запуска, при этом музыкальные файлы на NAS нельзя изменять, а секреты нельзя хранить в базе или передавать через API.

## Решение

Application-контейнер сам управляет CIFS-монтированием в фиксированную точку `/music`, получает только необходимую для этого capability `SYS_ADMIN`, всегда монтирует шару read-only и читает учётные данные только из окружения.

## Почему

Монтирование шары на Docker-хосте отвергнуто, потому что тогда веб-настройки не могут применить новый адрес без отдельного административного шага вне сервиса. Статический CIFS-volume в Compose отвергнут, потому что изменение подключения потребовало бы пересоздания конфигурации и контейнеров. Передача произвольной точки монтирования или секретов через API отвергнута из-за расширения командной поверхности и риска раскрытия учётных данных.

## Последствия

Подключение можно менять во время работы, а доступ к NAS ограничен чтением и одним путём. Контейнер остаётся привилегированнее обычного приложения из-за `SYS_ADMIN`; эксплуатация должна сохранять фиксированную точку монтирования, изоляцию секретов и запрет публикации управляющего API в недоверенную сеть.
