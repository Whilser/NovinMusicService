## Контекст

Веб-интерфейс поставляется вместе с небольшим домашним сервисом в одном контейнере; отдельная frontend-инфраструктура увеличивает сборочную и эксплуатационную поверхность.

## Решение

Интерфейс реализуется как самостоятельные HTML, CSS и нативные ES-модули без Node-based шага сборки.

## Почему

SPA-фреймворк с bundler отвергнут, потому что добавляет второй toolchain, lockfile, сборочный этап и регулярное сопровождение зависимостей ради одного локального интерфейса. Серверный HTML с полной перезагрузкой страниц отвергнут, потому что плохо подходит для постоянно обновляемого состояния плеера и отзывчивых локальных действий. Готовый тяжёлый UI-комплект отвергнут, потому что затрудняет точную визуальную адаптацию и приносит неиспользуемую зависимость.

## Последствия

Образ и цикл поставки остаются простыми, а статические файлы можно обслуживать напрямую. Команда принимает ручное управление состоянием, маршрутизацией и компонентными соглашениями; при существенном росте интерфейса переход на framework потребует переписать значительную часть frontend-слоя.
