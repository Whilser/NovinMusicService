# Спецификация: Novin Music Service

## Задача

Музыка хранится на SMB-шаре NAS, а воспроизводится уже установленным на сервере `novin` MPD. Пользователю нужен единый красивый веб-интерфейс, который сам индексирует файлы, хранит личную организацию библиотеки и управляет воспроизведением, не превращая MPD в хранилище плейлистов и оценок.

## Решение

На `novin` запускается Docker Compose-сервис. Он монтирует SMB-шару только для чтения, индексирует метаданные и обложки в собственную SQLite-базу, показывает адаптивную медиатеку в стилистике Apple Music и отправляет выбранные относительные пути во временную очередь MPD. Плейлисты, оценки и избранное существуют только внутри Novin Music Service.

## Решения по реализации

### Стек и поставка

- Backend: Python 3.12, FastAPI, стандартный `sqlite3`, Mutagen для тегов. Причина: компактный образ, прямой доступ к файловой системе и простое тестирование доменной логики.
- Frontend: самостоятельный HTML/CSS/ES-модули без Node-сборки. Причина: интерфейс остаётся быстрым и не требует второго toolchain в домашнем Docker-сервисе.
- Docker Compose: один application-контейнер с `cifs-utils`, capability `SYS_ADMIN`, read-only mount point `/music` и volume `/data`. Причина: адрес и имя SMB-шары должны применяться из веб-настроек без пересоздания compose-файла.
- SQLite в WAL-режиме. Причина: один домашний экземпляр и один профиль не требуют внешней СУБД.

### SMB и индексирование

- Настройки SMB: `host`, `share`, необязательные `domain` и `options`; mount point фиксирован `/music`.
- `SMB_USERNAME` и `SMB_PASSWORD` читаются только из окружения. Если оба пусты — `guest`; пароль не возвращается API и не пишется в SQLite/логи.
- Разрешены `.mp3`, `.flac`, `.m4a`, `.aac`, `.ogg`, `.opus`, `.wav`, `.aiff`; неподдерживаемые и нечитаемые файлы учитываются в результате сканирования, но не рушат его.
- Сканирование сначала строит снимок во временных таблицах, затем одной транзакцией согласует основную базу. Уникальный ключ трека — нормализованный относительный POSIX-путь.
- Метаданные: title/album/artist/album artist/track/disc/year/genre/duration; отсутствующие значения выводятся как «Без названия», «Неизвестный исполнитель», «Неизвестный альбом».
- Обложка выдаётся через API с ETag и ограничением размера; путь никогда не принимается от клиента напрямую.

### MPD

- MPD-клиент использует текстовый TCP-протокол и сериализует команды через короткие соединения с таймаутом.
- Настройки: `host` (по умолчанию `host.docker.internal`), `port` (`6600`), `uri_prefix`, пароль — только `MPD_PASSWORD` из env.
- В Compose добавляется Linux mapping `host.docker.internal:host-gateway`.
- Сервис никогда не вызывает `save`, `load`, `playlistadd`, `playlistdelete` или иные команды сохранённых плейлистов MPD. Разрешены только текущая очередь и транспорт.
- URI для MPD = нормализованный `uri_prefix` + относительный путь SMB. Выход за корень, NUL и управляющие символы отклоняются.
- Состояние плеера опрашивается UI раз в 2 секунды; ошибки получают короткий таймаут и не блокируют библиотечные API.

### Данные

- `tracks`: путь, метаданные, размер/mtime, duration, cover reference, timestamps.
- `playlists`: id, name, timestamps; `playlist_tracks`: playlist_id, track_id, position с каскадным удалением.
- `track_preferences`: track_id, rating 0–5, favorite boolean.
- `settings`: только несекретные SMB/MPD параметры.
- `scan_runs`: status, counters, message, timestamps; одновременно активен максимум один запуск.

### HTTP API

- `/api/health`, `/api/settings`, `/api/settings/test-smb`, `/api/settings/test-mpd`.
- `/api/scan` (POST start, GET current/result).
- `/api/tracks`, `/api/albums`, `/api/artists`, `/api/covers/{track_id}` с поиском и пагинацией.
- `/api/playlists` и `/api/playlists/{id}/tracks` для CRUD и сортировки.
- `/api/tracks/{id}/preference` для rating/favorite.
- `/api/player/status`, `/api/player/command`, `/api/player/play` для MPD.
- Ошибки имеют стабильную форму `{error: {code, message, details?}}`; пользовательский ввод возвращается в форме после ошибки.

### Интерфейс

- Левая полупрозрачная навигация, центральный каталог, закреплённый нижний mini-player; на телефоне — нижняя навигация и компактный плеер.
- Домашняя страница показывает недавно добавленное, альбомы и избранное; списки используют единый компонент строки трека.
- Контекстные действия доступны и мышью, и с клавиатуры; видимый focus, достаточный контраст, `prefers-reduced-motion`.
- Оптимистичны только обратимые локальные действия (избранное/оценка); управление MPD подтверждается серверным статусом.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `catalog` | SQLite-схема, запросы библиотеки, предпочтения, плейлисты | `Catalog` с операциями поиска, scan reconciliation, preferences и playlist CRUD | SQL, транзакции, миграции |
| `scanner` | обход `/music`, чтение тегов и поиск обложек | `scan(root) -> ScanSnapshot` | Mutagen, ошибки отдельных файлов, нормализацию путей |
| `share` | состояние SMB mount | `ShareManager.apply(settings)`, `.status()` | mount/umount, credentials file, subprocess |
| `mpd` | протокол и отображение текущей очереди | `MpdClient.status()`, `.command()`, `.play_uris()` | TCP framing, auth, escaping и запрещённые команды |
| `api` | HTTP-контракты и фоновые scan jobs | FastAPI routes | преобразование ошибок и оркестрацию модулей |
| `web` | Apple Music-подобное SPA-состояние и представление | статические assets, обращения только к `/api/*` | DOM rendering, responsive layout, polling |

Главные тестовые швы: публичные `Catalog`, `Scanner`/`ShareManager` и `MpdClient`; HTTP проверяется через FastAPI test client, браузерная логика — через чистые функции состояния и smoke-проверку DOM.

## Безопасность и ограничения

- Сервис задуман для доверенной домашней сети и намеренно не имеет авторизации (G02). Публиковать порт в интернет нельзя; это явно указано в README.
- Контейнер получает `SYS_ADMIN` только для CIFS mount. SMB mount всегда read-only и ограничен фиксированной точкой; произвольные команды или пути из API не исполняются.
- Секреты задаются только в `.env`, который игнорируется Git. `.env.example` содержит только пустые имена.

## Вне рамок

- Несколько пользователей и раздельные профили: бриф описывает личный сервис и не требует учётных записей.
- Загрузка, редактирование или удаление файлов на NAS: шара монтируется только для чтения.
- Сохранённые плейлисты и база MPD: прямо запрещено G01.
- Транскодирование и воспроизведение звука в браузере: звук выводит MPD по R05.
- Автоматическое фоновое расписание сканирования: заказана ручная кнопка R07.

## Открытые места

Открытых пользовательских фактов нет. Адрес и имя SMB-шары, MPD host/port и URI-префикс задаются после запуска. Секретные значения, если понадобятся, пользователь вписывает в `.env` самостоятельно.
